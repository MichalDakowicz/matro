# Matro 0.7.0

Playback continues downloading to temporary device storage through the end of a movie, including while paused. Desktop and web playback use disk-backed buffering; Android downloads a temporary local copy and switches to it when complete. The timeline shows buffered media, and temporary buffers are removed when leaving playback or changing streams.

Playback positions are checkpointed locally before server saves. Reopening after a page crash restores the newest local or server position for that account, and recovered browser progress syncs back to the server. Startup and seek timestamp resets no longer overwrite resume positions. Prepared streams build an initial cushion and recover from premature stream endings.

Desktop, web, server and native mobile now share one workspace. The Android app uses native library and player screens with remembered track choices, download management, and server folder controls. The server prepares compatible playback ahead on disk and selects a usable hardware encoder with a software fallback.

Validation includes real-media playback/cache tests, server API tests, desktop/web playback and persistence checks, a paused-decoder full-download/cleanup regression, a forced renderer-crash recovery test with server saves unavailable, and native client tests and type checking.

Windows installers remain unsigned. Android updates preserve the existing application ID and signing certificate. Recovery resumes from the last stored checkpoint; abrupt machine power loss was not simulated.
